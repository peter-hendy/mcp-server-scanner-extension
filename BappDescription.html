This extension security-tests Model Context Protocol (MCP) servers. It discovers their tools, resources, resource templates and prompts. It builds JSON-RPC 2.0 requests with fuzzable insertion points and runs its MCP checks against them, either on their own or alongside Burp Scanner's built-in checks.

It supports modern server/discover HTTP, initialize-based Streamable HTTP and legacy SSE. Authentication can be none, detected automatically, a bearer token, a custom header, or OAuth 2.1 with PKCE (pre-registered clients, Client ID Metadata Documents or dynamic client registration, plus the client credentials grant).

17 scan checks (headline severity in brackets):

  • Unauthenticated request execution (High).
  • Session binding across identities (High): a stateful session that returns one user's result to another user's credential, or that another user's credential rebinds.
  • Origin/Host admission, the DNS rebinding precondition (Medium), and cross-origin reads allowed by CORS (High).
  • Command injection (High), including argument injection where a value is parsed as a command-line option (Medium), file path traversal (High), SQL injection (High) and downstream route escape (Information) in every MCP field.
  • Outbound requests (Medium, Collaborator), including payloads placed after a URL's own host to pass prefix allowlists, and OAuth registration URL fields.
  • SSRF address filter bypass (High, Collaborator): a fetch tool that refuses loopback but accepts it in an alternate address spelling.
  • JWT access token validation (High), OAuth refresh grant validation (Medium), OAuth redirect policy (Medium) and consent page structure reflection (Information).
  • OAuth authorization without login or consent. High when the issued code redeems to a token that opens a request the server refused without one. Medium when a code is issued with no login or consent page. Information when the endpoint already answers without a token.
  • OAuth authorization code reuse: Medium when a second sequential or concurrent redemption of one code returns a working token.
  • Sibling-route authentication parity: Low when the main MCP route refuses an anonymous catalog listing but a sibling route or the advertised SSE message route answers it.
  • Session lifecycle, using the scanner's own probe sessions only. High when session IDs are guessable and a bare ID runs a request without credentials. Low for guessable IDs alone, or when a session still answers after a successful DELETE.
  • Cross-client response leak: High when concurrent clients that send the same JSON-RPC id receive each other's tool results, and distinct ids stop the crossing.

Access control testing: define a primary user and compared users, each with their own credentials, and the access each should have. In the Access tab, Collect IDs gathers the object IDs each user owns from the server's replies, then Check access replays the primary user's calls as every compared user and as an anonymous client. It reports operations a lower-privilege user can run (High) and, where a private marker proves it, results returned to another user (High).

Requires Burp Suite Professional. Collaborator is required for out-of-band detection.
