# MCP connection core

Java 17 composition of `mcp-protocol-core` and `mcp-oauth-core`. Contains no network implementation, JSON library, browser launcher, Burp dependency, or token exchange algorithm.

Build and test it from the repository root with `./gradlew :mcp-connection-core:build`, which builds the protocol and OAuth modules first.

Distribute all three binary JARs. The connection JAR does not shade its dependencies. The tests include an external consumer in another package that uses only the public API.

## Public contracts

- `CredentialProviderRegistry` returns immutable registries through `with(id, provider)`. Unknown IDs fail closed. `none` is registered by default.
- `CredentialProviders.none()`, `.bearer(token)`, and `.custom(headers)` cover static authentication. Header names and values are validated; credentials cannot override transport framing or protocol negotiation headers.
- `OAuthCredentialProvider` takes a `CredentialBinding`, `OAuthCredentialAccess`, and an approval function receiving the proposed scope set. `OAuthCredentialAccess` adapts the shared OAuth engine and its credential store. It owns obtaining current credentials and calling engine refresh/authorization, including adapter-specific serialization. The provider retains configured, currently granted, and previously approved scopes across operations, and delegates challenge parsing, resource binding validation, challenged scope union, and retry decisions to `mcp-oauth-core`.
- `McpConnection.openHttpSession` is the default HTTP integration path: retain its `HttpSession`, create requests through `session()`, and send them through `send(request)`. A complete session-not-found 404 after token recovery triggers one initialize handshake using the negotiated legacy version and a replay with the replacement session ID. The total operation budget is three sends. Null, incomplete, and ambiguous responses never trigger session replay; recovery cannot change protocol version or probe modern HTTP.
- `McpConnection.openInitializeHttpSession(port, name, version, preferredVersion)` opens initialize-based HTTP directly and returns the same recoverable `HttpSession`. It never probes modern HTTP; session recovery retains the negotiated version and credential provider.
- `McpConnection.openInitializeHttpProbe(port, deletePort, name, version, preferredVersion)` opens initialize-based HTTP as a probe. `HttpProbeSession` never reinitializes or replays after session-not-found, so a dead session stays observably dead; credential challenge recovery still applies. `sessionId()` exposes the server-issued `MCP-Session-Id` (empty when stateless). `send(request)` always carries that ID, including after termination. `terminate()` sends the `SessionDeletePort` a credentialed DELETE with `MCP-Session-Id` and `MCP-Protocol-Version` and returns the server's response unchanged; it fails when no ID was issued. `close()` terminates a session not already terminated. When the handshake fails after the server issued an ID (for example, `notifications/initialized` is refused), the probe sends that ID the same DELETE before rethrowing the failure; a failed cleanup DELETE is attached as a suppressed exception.
- `McpConnection.openSseProbe(factory, origin, name, version)` opens legacy SSE as a probe. `SseProbeSession` never opens a second stream once the handshake completes: any later stream failure ends it, and a credential challenge on a later POST is rethrown as the `SseOpenException` carrying the server's response instead of being recovered. `sessionId()` reads the `session_id` (Python SDK) or `sessionId` (TypeScript SDK) query parameter of the endpoint event, URL-decoded; an empty value is no ID. `SseSessionIds.from(endpoint)` exposes the same rule so adapters can recognise a legacy SSE message endpoint (and must not open an HTTP probe there). SSE has no termination request, so `terminate()` closes the GET stream and reports no status; reuse of the old endpoint goes through the adapter's own POST.
- `McpConnection.openHttp` remains compatible for adapters managing their own session lifecycle. It delegates negotiation to `McpFlow`. Authentication refusal aborts negotiation before a different protocol version can be attempted. `send` authenticates each request and bounds execution to three attempts. Approval and denial produce a sanitized `ConnectionAuthException`.
- `SseStreamFactory.open(headers)` must open a **fresh** SSE GET stream using the supplied credential headers. It returns a stream owning its GET connection and message POST adapter. An unsuccessful GET signals `SseOpenException` with the bounded HTTP response; this lets the connection core apply the same recovery policy before opening another stream. The factory must close any failed GET response itself.
- `SseSession.call(request, McpRequestId)` returns a generic reply correlated by exact ID type and value; the numeric overload remains available.
- `openSse` authenticates every handshake POST and subsequent `SseSession.call`, and closes streams on failed initialization. `SseSession` is `AutoCloseable`. The POST endpoint remains in the form returned by protocol-core; the network adapter resolves validated relative endpoints against the configured origin.
- `anonymous()` creates an isolated context without credential reads, refresh, authorization, or approval. Every anonymous `openSse` calls the stream factory independently with empty credential headers. Existing authorization, cookies, and declared custom credential headers are removed from outgoing requests. Providers declare custom credential names using `headerNames()` without reading secrets or triggering a token flow.

Network adapters retain bounded reads, endpoint/origin enforcement, redirect policy, TLS, actual GET/POST execution, stream event delivery, and cancellation. Authentication decisions do not select protocol versions. Each recovery state belongs to one HTTP send, SSE connection opening, or SSE call. A GET or POST authentication challenge that permits recovery closes the old stream, opens a new GET with updated credentials, and performs a new handshake before replay. Credential changes detected before a POST also force reconnection. Recovery and reconnection are bounded to two attempts per logical operation; GET and POST always share one credential snapshot.

The matrix verifies SSE `2024-11-05`, initialize HTTP `2025-03-26`, `2025-06-18`, `2025-11-25`, and modern HTTP `2026-07-28` with anonymous, bearer, custom headers, and OAuth credentials. It exercises negotiation and named operations through real shared protocol code.
